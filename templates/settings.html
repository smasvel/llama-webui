Settings

Where this app reaches each backend, and the credentials it sends — shown in plain text since this page is already admin-only. Overrides here take effect immediately (no restart) and persist across restarts — clear a field to fall back to whatever .env has (or nothing, if .env doesn't set it either).

Service controls

Restart the local llama.cpp engine if a coding client is stuck, or restart the llama-web app itself. The engine reloads its configured GGUF on start.

llama.cpp engine

The local llama.cpp engine serves GGUF models from the llama-web model library. Its endpoint is configured in server.conf and authenticated with the engine key; models are loaded from the Models page.

opencode.ai (remote hosted models)

Connects llama-web to the opencode.ai hosted model catalog (GPT/Gemini/GLM and more) through its OpenAI-compatible inference endpoint with your opencode.ai API key. Models are discovered automatically; download and deletion stay with the opencode.ai account. The key is stored encrypted in PostgreSQL and only sent to opencode.ai. Test connection saves the selected plan and key. Models appear in Chat, on the Models page, in agent assignment pickers, and in Model tests immediately after a successful test. Failed checks show the response returned by opencode.ai. Get a key at https://opencode.ai/console.

Default LAN model (OpenCode)

Which model OpenCode's generated config (Help page) defaults to, grouped by serving backend. Each option also shows the compute path reported by that backend; choose an option marked NPU for full NPU inference (a model name ending in “NPU” does not guarantee that its installed recipe uses the NPU). "Auto" picks whatever's already loaded, falling back to the Ryzen AI NPU model — good for a quick warm start, but the NPU is slow enough (~5 tok/s) that a large coding turn can outlast OpenCode's own client-side timeout and look like it "didn't respond." Pin a specific faster backend here instead if that keeps happening; this only changes the default — every model is still listed and selectable in OpenCode/Continue's config either way.

Web search and research

Controls when llama-web searches and opens result pages. Playwright opens relevant organic pages, blocks ad and tracker requests, and does not click page controls. Higher page limits support broad research while relevance and domain diversity keep fetched pages focused. Disabling browser access still permits snippets.

Checking MCP tool servers…

Set pages to 0 for snippet-only research. Irrelevant and duplicate-domain results are skipped. Direct URLs are opened only when both direct URLs and Playwright are enabled.

Tailscale

A second reachability path alongside the LAN, for a device that's on this machine's Tailscale tailnet — same Caddy ports, same bearer tokens, same CA cert, just a different IP. The Help page's LAN config always stays LAN; when this is on, it also shows a second, independent Continue/OpenCode config pair pre-built with the Tailscale IP — both are shown together, nothing gets replaced. See the Help page for the full DNS links for the browser app and certificate download. Backend API configs use the numeric Tailscale IP on their Caddy ports.

Chat request limits

Ceilings the app enforces on llama-web's own chat requests. A request that doesn't ask for a specific max_tokens uses Default max tokens, which ships set to the cap. Clear a field to restore its built-in default. These do not affect OpenCode/Continue, which talk to the backends directly.

Higher values allow longer multi-step tool use. This applies to llama-web chat and does not change OpenCode/Continue.

OpenCode compaction

Automatic compaction is on by default so OpenCode summarizes older turns before the loaded context fills. A model still has a finite context window; if a turn exceeds its loaded limit, use a larger model or increase its loading ctx-size. Turn compaction off to keep the full transcript when you prefer. Leave Keep and Buffer blank to size them from the selected model's loaded context. Overrides are bounded by the context-based safety formula.

OpenCode context

Also baked into the generated OpenCode config. When on (default), each model advertises the context its backend is actually loaded with, so OpenCode never builds a request larger than the server's real window — a real report had a model loaded at 8192 while the config claimed 32768, producing "request (29899 tokens) exceeds the available context size (8192 tokens)". Turn this off to always advertise the fixed per-backend defaults. Fallback context applies only to models whose real context can't be detected (e.g. not currently loaded); leave it blank to keep each backend's tuned default.

Caddy (LAN access)

Read-only — parsed live from /etc/caddy/Caddyfile (this app doesn't write to it; edit that file and reload Caddy yourself to change anything here). Same CA cert as the Help page's Continue/OpenCode configs; the token shown below is the general-purpose "lan" one (manual/ad-hoc use) — OpenCode and Continue each get their own dedicated token, embedded directly in their generated configs in the Help page, not shown here.

Tailscale (via Caddy)

Optional manual Tailscale address override. When left blank, llama-web detects the address from the local Tailscale interface and uses it in generated client configurations.
