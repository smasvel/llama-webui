Help

llama-web serves chat from a local llama.cpp engine. The web UI and API listen on 18474 over HTTPS, the local Caddy gateway on 18471, the engine on 18473 (loopback only), and PostgreSQL on 18472. Model files stay in the llama-web model library. Each browser login uses its own per-port session cookie, so other local installs and cookies from older builds cannot sign you in here.

Chat

Answers render headings, bullet and numbered lists, tables, code blocks, inline HTML and images, and common emoji shortcodes. Saved chats can be regenerated, edited or deleted. Ask for a live lookup to let chat use the local Playwright browser tools, or for a calculation to use the Python REPL. Attachments, voice input and spoken replies are available where the selected model supports them.

Troubleshooting

No model is selectable in Chat

Download a GGUF from Downloads or upload one from Models, then load it on the Models page. The engine serves one model at a time; the loaded model is the one chat uses.

Tool calls are not running

Ask explicitly for a live lookup or a calculation. MCP browser tools, the Python REPL and live search are on by default; browser tools need a working Chromium, and the Python REPL uses the app's virtualenv. Check Settings → Web search and research (Enable MCP browser tools / Enable Python tool) and the live logs if a tool is unavailable.

Chat answers look plain or show JSON

Refresh the page: formatting is rendered in the browser. Tool payloads are shown as readable tool calls, tables or bullets; the raw form is only kept for copied text when applicable.

A large model will not load

Pick a smaller quantisation or lower the context size on the Models page. Some GGUF formats need engine support this host does not have; the Models page reports load errors and the engine log has details.

HTTPS certificate warning

Trust the local certificate using Step 1 above. The certificate is regenerated automatically when it expires; after regeneration, trust the new copy shown here.
